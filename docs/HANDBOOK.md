# Справочник лаборатории

> Этот файл был README до этапа 2 и описывает устройство подробно: язык
> запросов, все команды, отчёты, арену, замеры и сверку с апстримом. Всё
> это в силе. Устарели ровно два места, и они помечены ниже: тело и
> сенсорный вход с тех пор появились, а окно управления теперь своё, не
> браузерное. Краткое описание проекта и его нынешнее состояние — в
> [README.md](../README.md), полная приёмка со всеми числами —
> в [lab/flybrain/FULL_LOOP_VALIDATION.md](../lab/flybrain/FULL_LOOP_VALIDATION.md).


Эмулятор целого мозга дрозофилы (коннектом FlyWire) плюс обвязка вокруг него:
выбор нейронов на человеческом языке, запись активности по времени, 3D-карта
мозга с анимацией и агент на локальной модели, который сам ставит опыты.

```
D:\fly-brain
├─ upstream\      клон github.com/eonsystemspbc/fly-brain (не трогаем)
├─ lab\           наш код: flybrain/ + assets/ (страницы пульта)
├─ cache\         аннотации FlyWire, таблица нейронов, матрица весов
├─ out\           результаты прогонов, HTML-отчёты и index.html
├─ .venv\         python 3.12 + torch 2.11 cu128
├─ ui.cmd         окно управления: всё мышкой, картинка вживую
├─ console.cmd    консоль, которая не закрывается
├─ fly.cmd        командная строка
├─ fix-venv.cmd   починка окружения
├─ add-to-path.cmd  чтобы работало просто `fly`
└─ smoke.cmd      проверка, что все команды запускаются
```

## Это полный мозг мухи?

Коннектом — да, полный. Модель мозга — очень упрощённая.

**Что настоящее.** Это вся реконструкция FlyWire v783: 138 639 нейронов и
15 091 983 связи между ними, то есть каждый нейрон мозга взрослой дрозофилы и
каждая синаптическая связь, которую нашли при трассировке ЭМ-объёма FAFB. Это
тот же набор данных, что в статье Dorkenwald et al., Nature 2024, и
динамическая модель та же, что у Shiu et al., Nature 2024 (Philip Shiu — автор
и этого репозитория, он сейчас в Eon Systems).

**Чего в нём нет.**

* Каждый нейрон — точка. Ни дендритного дерева, ни того, что разные ветви
  одной клетки могут работать независимо. Реальный нейрон мухи так не устроен.
* Вес связи = число синапсов × 0,275 мВ. Одинаково для всех. Настоящая сила
  синапса так не измеряется.
* Знак связи взят из предсказанного нейромедиатора (ацетилхолин +, ГАМК и
  глутамат −). Предсказание по ЭМ-изображению, с точностью около 87 %.
* Нет нейромодуляции: дофамин, октопамин, серотонин и нейропептиды работают
  как обычные быстрые синапсы, хотя в живой мухе они меняют состояние сети на
  секунды и минуты. Голод, возбуждение, сон так не воспроизвести.
* Нет пластичности и обучения вообще.
* Нет грудного ганглия (VNC). Мотонейронам мозга некуда посылать сигнал:
  исполнители ходьбы и полёта лежат в VNC, а его в этих данных нет.
  **Устарело в части тела:** тело NeuroMechFly v2 в MuJoCo с тех пор
  появилось (раздел «Тело» ниже), но связь «нисходящие нейроны → ноги» в
  нём — объявленный инженерный интерфейс, а не восстановленная проводка.
* **Устарело:** сенсорный вход с тех пор появился — запах на антенны, вкус
  на лапки и кадр обоих сложных глаз на 10 582 фоторецептора. Ручная подача
  («зажечь такие-то рецепторы») осталась как отдельный режим.

То есть это не «муха в компьютере», а проводка мухи с простейшей физикой
проведения сигнала. На ней воспроизводятся конкретные вещи: подал сахар на
вкусовые нейроны — через 10–40 мс активируются мотонейроны хоботка; статья
Shiu et al. сравнивала такие предсказания с экспериментами и, по заявлению
авторов, получила 91 % попаданий. Всё, что сложнее одного рефлекса, модель
не держит.

## Установка (уже сделана)

```bash
git clone --depth 1 https://github.com/eonsystemspbc/fly-brain.git upstream
uv venv --python 3.12 .venv
uv pip install --index-url https://download.pytorch.org/whl/cu128 torch
uv pip install "pandas>=2.2,<3" "numpy<3" pyarrow scipy tqdm
```

Апстрим рассчитан на Ubuntu/WSL с шестью бэкендами (Brian2, Brian2CUDA,
PyTorch, NEST GPU, GeNN, Brian2GeNN) — из них только PyTorch ставится на
Windows без возни с nvcc, поэтому лаборатория использует его. Остальные
бэкенды нужны апстриму для замеров скорости, а не для расчёта.

Считает на RTX 4090 примерно 1200 шагов/с при шаге 0,1 мс, то есть секунда
жизни мухи ≈ 8 секунд расчёта.

### Карта мозга

Таблица нейронов в апстриме содержит только ID — ни имён, ни координат, ни
областей. Их даёт отдельный датасет: аннотации FlyWire v783 из статьи
Schlegel et al. 2024 (`cache/annotations_783.tsv`, скачивается командой
`fly fetch-annotations`). Оттуда берутся тип клетки, класс, нейромедиатор,
сторона и координаты сомы — без них не было бы ни карты, ни 3D.

Область мозга (нейропиль) каждому нейрону ставится так:

| источник метки | нейронов | как |
|---|---:|---|
| `optic_family` | 77 556 | семейство оптических долей (Tm9, T4a, L2 → медулла, лобула, ламина) |
| `cell_type` | 23 344 | имя типа начинается с аббревиатуры нейропиля (AVLP429 → AVLP, ER4d → EB) |
| `cell_class` | 19 908 | класс клетки (gustatory → GNG, Kenyon_Cell → MB) |
| `super_class` | 7 460 | супер-класс (descending → GNG, motor → нерв) |
| `knn_soma` | 10 357 | голосование 15 ближайших сом среди уже размеченных |
| нет | 14 | нейроны без аннотаций |

Всего 36 областей по номенклатуре Ito et al. 2014. Субэзофагеальная зона (SEZ)
здесь называется своим анатомическим именем GNG — там и вкусовые входы, и
мотонейроны хоботка. Это приближение: честный нейропиль считается по положению
синапсов, а здесь — по имени типа и месту сомы. Для «куда пошёл сигнал» этого
достаточно, для анатомической статьи — нет.

## Окно управления в браузере (прежнее)

> **Устарело как главный путь.** Основное окно теперь своё, нативное, на
> Taichi/Vulkan: `app.cmd` или `fly app`. Браузерный пульт остался и
> работает, описание ниже про него.

Двойной клик по **`ui.cmd`** — и дальше всё мышкой, без командной строки:

```bash
D:\fly-brain\ui.cmd
```

Откроется браузер с пультом. Слева параметры, в середине мозг, справа цифры.
Картинка идёт **во время счёта**, а не после: кадры активности уходят в
браузер по мере того, как считается каждый шаг записи.

* **Стимуляция** — вписываете запрос («кого зажечь»), и прямо под полем
  видно, сколько нейронов он находит и в каких областях; рядом готовые
  кнопки: сахар, запах, запах без грибовидного тела, удар, вперёд. Частота,
  окно импульса, кого выключить, длительность.
* **Арена** — выбираете популяцию на рулёжку из выпадающего списка (те самые
  63 кандидата, что перебирает `fly lateral`), постоянную интегрирования,
  контроль с переставленными антеннами, комментарий локальной модели. Внизу
  появляется арена: поле запаха, след, муха и живые шкалы — запах по каждой
  антенне, выход на рулёжку, скорость, поворот, расстояние до еды.
* Справа области обновляются на каждом кадре, по клику на название остаётся
  только эта область. Кнопка **Сохранить прогон** кладёт его в `out/` ровно
  так же, как это делает командная строка, с обычным отчётом.

Главное, что даёт окно помимо удобства: **коннектом и матрица связей остаются
в памяти между прогонами**. В командной строке каждый запуск платит несколько
секунд на загрузку, здесь — один раз при старте сервера, дальше «Пуск»
отвечает сразу.

Считает то же самое, что и командная строка: на одинаковых параметрах
таблица активных нейронов совпадает нейрон в нейрон (APL 195,0 и 191,7,
lLN1\_bc 180,0 и так далее).

Закрыть — Ctrl+C в окне консоли, которое открылось вместе с пультом.

## Командная строка

```bash
D:\fly-brain\fly.cmd doctor           # всё ли на месте: окружение, данные, GPU, Ollama
D:\fly-brain\fly.cmd                  # список команд и быстрый старт
D:\fly-brain\fly.cmd index            # одна страница со всеми прогонами
D:\fly-brain\fly.cmd regions          # какие области есть и сколько в них нейронов
D:\fly-brain\fly.cmd select "class:gustatory+side:left"
```

**Если запускаете мышкой:** для работы мышкой есть `ui.cmd` (окно управления,
см. выше) и `console.cmd` — он открывает консоль, которая остаётся, сразу в
папке проекта и с командой `fly` в её PATH. Двойной клик по самому `fly.cmd`
покажет справку и подождёт нажатия клавиши: иначе окно закрылось бы сразу
после отработки команды и вывод увидеть было бы нельзя.

В PowerShell путь нужен целиком (`D:\fly-brain\fly.cmd doctor`) или с
`.\` — в отличие от cmd, PowerShell не запускает файлы из текущей папки.
`add-to-path.cmd` добавляет папку в PATH пользователя, после чего в **новом**
окне работает просто `fly doctor`. Запускать его надо самому — автоматически
ничего в окружение не прописывается. `smoke.cmd` прогоняет все команды разом
и говорит, что из этого запустилось, `fix-venv.cmd` чинит сломанное
окружение.

### Общая страница

`fly index` собирает `out/index.html` — хаб по всему, что посчитано:
одиночные опыты с их активными областями, эпизоды на арене с метриками
наведения, серии с контролем в виде таблиц, перебор популяций и журнал агента
со ссылками на каждый его опыт. Из любого отчёта туда ведёт ссылка «← все
прогоны». `fly index --rebuild` заодно пересобирает сами отчёты.

### Язык запросов

Через запятую — объединение, через `+` — пересечение.

| селектор | что значит | пример |
|---|---|---|
| `type:` | имя типа клетки, регулярка | `type:MBON0[1-5]` |
| `type=` | точное имя | `type=DNa02` |
| `class:` | класс клетки | `class:gustatory`, `class:Kenyon_Cell` |
| `super:` | супер-класс | `super:descending`, `super:motor` |
| `region:` | область мозга | `region:MB`, `region:EB` |
| `nt:` | нейромедиатор | `nt:gaba`, `nt:dopamine` |
| `side:` | сторона | `side:left` |
| `id:` | root_id FlyWire | `id:720575940627652358` |

### Опыты

```bash
rem сахар на левой лапке, импульс 100-400 мс
fly run -a "class:gustatory+side:left" -r 200 --t 0.6 --pulse 100 400

rem ходьба вперёд: пара нейронов P9, во FlyWire они зовутся DNp09
fly run -a "type=DNp09" -r 100 --t 1.0

rem запах: обонятельные рецепторы -> антеннальная долька -> грибовидное тело
fly run -a "class:olfactory+side:left" -r 150 --t 0.8 --pulse 100 500

rem то же, но с заглушённым грибовидным телом - видно, что изменилось
fly run -a "class:olfactory+side:left" -r 150 --t 0.8 --silence "type:KC"

rem зрение: детекторы петли LC
fly run -a "type:LPLC2" -r 150 --t 0.6 --pulse 100 350

rem снять всё торможение в центральном комплексе
fly run -a "class:gustatory" -r 200 --silence "region:EB+nt:gaba" --t 0.6
```

`fly demos` прогоняет готовый набор из пяти опытов (вкус, запах, запах без
грибовидного тела, надвигающийся объект, команда «вперёд») — пара минут,
матрица связей грузится один раз на все пять.

Каждый прогон кладёт в `out/<имя>/`:

* `report.html` — отчёт, открывается сам;
* `rates.parquet` — частота каждого активного нейрона;
* `bins.npz` — растр активности по бинам;
* `meta.json` — параметры прогона.

`fly report <имя>` пересобирает HTML из сохранённого прогона, не считая заново.

## Отчёт

Один HTML-файл без интернета и без зависимостей, около 1,5 МБ. Внутри —
WebGL-облако из всех 138 639 сом в координатах FlyWire.

* **Активность** — сработавшие нейроны горят по частоте (цветовая шкала magma),
  фон остаётся серым силуэтом мозга. Активность сглажена экспонентой с
  τ = 50 мс, как кальциевый индикатор, поэтому волна видна как след.
  Стимулированные нейроны подсвечены голубым.
* **Области** — тот же мозг, раскрашенный по нейропилям.
* Названия областей висят в 3D на медиане сом своего нейропиля и разгораются
  вместе с ней — это и есть карта.
* Мышь: тащить — вращать, колесо — зум, наведение на активный нейрон — тип,
  класс, медиатор, частота. Пробел — пуск/пауза, стрелки — по кадрам.
* Справа: области по пиковой частоте и по моменту прихода сигнала, полная
  карта областей с числом нейронов (клик — показать только эту область),
  тепловая карта «область × время» с бегунком, топ активных нейронов,
  параметры прогона.

Колонка «приход» — момент, когда область вышла на 20 % своего пика. По ней
читается порядок распространения сигнала, а не только сила отклика.

## Локальные модели

Всё через Ollama на `127.0.0.1:11434`, ничего не уходит наружу. Модель по
умолчанию — `gpt-oss:latest`, меняется через `--model` или `FLYBRAIN_MODEL`.

### Разбор результата

```bash
fly run -a "class:gustatory+side:left" -r 200 --t 0.6 --explain
```

Прогон сжимается до нескольких сотен токенов (какие области, с какой
задержкой, какие типы вели каждую) и уходит модели. Она пишет путь сигнала со
стрелками и задержками, что это значит для поведения и где модели верить
нельзя. Текст попадает в отчёт отдельным блоком.

### Агент-экспериментатор

```bash
fly agent "Через какие нейроны идёт путь от сахара до мотонейронов хоботка? Докажи заглушением." --steps 6
```

Модель получает четыре инструмента — `search`, `list_types`, `experiment`,
`conclude` — и бюджет шагов. Она сама ищет нейроны по именам, запускает
симуляции, читает сводку активности и подводит итог. Каждый её опыт
сохраняется со своим 3D-отчётом, ход мысли — в `out/<имя>/journal.md`.

Локальная модель охотно придумывает опыты, которых не ставила, поэтому в цикл
встроены три ограничителя:

* `conclude` не выдаётся как инструмент, пока не проведён хотя бы один
  настоящий `experiment`;
* итоговый вывод пишется отдельным запросом, где в контексте только
  фактические измерения — без её собственных рассуждений;
* если ни в одном опыте не было заглушения, к выводу приписывается пометка,
  что причинность не проверена.

В отчёт перед выводом подставляется список реально проведённых прогонов с их
стимулами и каскадами, так что любое утверждение можно сверить.

## Замкнутый цикл: муха на арене

```bash
fly arena --t 12                      # эпизод с комментарием модели
fly arena --t 12 --control            # то же, но антенны переставлены
fly arena --bench 6 --bench-t 4       # серия: норма против перестановки
fly arena --t 5 --probe --no-comment  # где теряется сторона запаха
```

Арена 60×60 мм, две кормушки, у каждой свой гауссов шлейф запаха. Каждые 20 мс:

1. считаются концентрации у левой и правой антенны, расстояние до стены
   впереди и факт стояния на еде;
2. это подаётся как частота Пуассона на **настоящие** сенсорные нейроны —
   1116 обонятельных слева, 1133 справа, 410 вкусовых, по сотне LPLC2 на
   каждую лобулу;
3. мозг считается 200 шагов по 0,1 мс;
4. считается средняя частота 645 нисходящих нейронов левого полушария и 646
   правого;
5. сумма даёт скорость, разница — поворот; муха едет, арена меняется.

**Что здесь настоящее, а что придумано.** Настоящий — только мозг в середине:
коннектом, уравнения, сверка с апстримом. Пункты 2 и 5 придуманы целиком. У
модели нет тела и нет грудного ганглия, поэтому превращения «запах → частота
рецептора» и «нисходящие нейроны → ноги» просто неоткуда взять — они
подобраны так, чтобы числа были правдоподобны. Все коэффициенты собраны в
`BodyParams` в [lab/flybrain/world.py](lab/flybrain/world.py), там же
отмечено, где пришлось отойти от биологии: расстояние между антеннами
увеличено до 2 мм (у настоящей мухи ~0,3 мм, и она ловит градиент рысканьем
головы, чего этот контур не умеет).

Так что эпизод — это «что получается, когда настоящую сеть прогоняют через
придуманное тело», а не поведение мухи.

### Работает ли оно

Как мера берётся среднее косинуса между курсом и направлением «в сторону
запаха»: случайное блуждание даёт 0 при любой геометрии арены. Считается через
`fly arena --bench`, где один эпизод — одно наблюдение. Это важно: внутри
эпизода соседние шаги сильно зависимы (поворот держится ~100 мс, направление
градиента — секунды), поэтому «доля шагов с поворотом в сторону запаха»
выглядит гораздо убедительнее, чем есть. Первый прогон дал по ней 62,7 % и
выглядел как успех — это была иллюзия автокорреляции.

**Выход со всех нисходящих нейронов: не работает.** Шесть эпизодов по 4 с на
условие:

| условие | совпадение с градиентом | до еды | визитов |
|---|---|---|---|
| норма | +0,422 ± 0,059 | −11,3 мм | 2 |
| антенны переставлены | +0,432 ± 0,067 | −11,7 мм | 2 |

Разницы нет. Прогоны с одинаковым сидом совпадают попарно (0,309 против 0,331,
0,591 против 0,653) — траектория определяется начальным курсом и шумом, а не
тем, какая антенна нюхает. Сами +0,42 это геометрия: муха стартует в углу с
низкой концентрацией, и почти любое движение вперёд сначала идёт вверх по
градиенту.

**Выход с проекционных нейронов антеннальной дольки: работает.** Шестнадцать
эпизодов на условие (две независимые серии, сиды 100–105 и 200–209):

| условие | совпадение с градиентом | прогонов с «+» | до еды | визитов |
|---|---|---|---|---|
| норма | **+0,142 ± 0,026** | 14 из 16 | −3,3 мм | 7 |
| антенны переставлены | −0,035 ± 0,051 | 8 из 16 | +1,2 мм | 1 |

Welch t = 3,07, p = 0,006. Муха идёт на запах и доходит до кормушки; с
переставленными антеннами перестаёт.

Читать это надо аккуратно. Норма воспроизводится хорошо: +0,135 в первой серии
и +0,146 во второй, 14 прогонов из 16 положительные. А вот контроль ведёт себя
неустойчиво: −0,128 в первой серии и +0,021 во второй, разброс вдвое больше
нормы (sd 0,205 против 0,106). То есть перестановка антенн **ломает** наведение,
а не аккуратно его переворачивает. На n = 16 этого хватает для вывода «сигнал
через сеть управляет траекторией», но не для утверждения «контур строго
инвертируется».

### Кто вообще кодирует сторону запаха

Сторона отлично живёт в проекционных нейронах антеннальной дольки, наполовину

в контуре управления участвует только обонятельный вход, а остальной мозг
висит сбоку. Получилась машинка Брайтенберга на настоящей антеннальной
дольке.

### Выживает ли наведение дальше по цепи

Три выхода, прогнанные одинаково (эпизоды по 4 с, контроль — переставленные
антенны):

| выход | r в открытом замере | n на условие | эффект (95 % ДИ) | p |
|---|---:|---:|---|---:|
| все нисходящие | +0,019 | 6 | −0,011 (−0,190…+0,169) | 0,91 |
| region:LAL | +0,242 | 30 | +0,055 (−0,029…+0,140) | 0,20 |
| ALPN | +0,882 | 16 | **+0,177** (+0,061…+0,292) | **0,006** |

На LAL наведение **не подтверждается**: p = 0,20 даже при 30 эпизодах на
условие. Но и не опровергается — доверительный интервал накрывает ноль. Что
он исключает, так это эффект уровня ALPN: если на LAL сигнал и есть, он
примерно втрое слабее. По еде направление стабильно в обеих сериях (−2,6 мм
против +0,6 мм, 6 заходов на кормушку против 2), но на числах это d Коэна
0,34, и чтобы отличить такое от нуля с мощностью 0,8 нужно около 137 эпизодов
на условие — часа три счёта, что уже не окупается.

Зато хорошо сходится другое: поведенческий эффект почти точно пропорционален
силе кодирования стороны, измеренной в **открытом** контуре.

| выход | доля кодирования от ALPN | доля эффекта от ALPN |
|---|---:|---:|
| все нисходящие | 0,02 | −0,06 |
| region:LAL | 0,27 | 0,31 |
| ALPN | 1,00 | 1,00 |

То есть дешёвый открытый замер `fly lateral` предсказывает, поедет ли
замкнутый контур, и его стоит гонять до того, как тратить часы на серии.

Любую из этих популяций можно поставить на рулёжку:

```bash
fly arena --t 12 --motor ALPN
```

Опорная частота, усиление поворота и собственный перекос сети калибруются в
начале эпизода: у разных популяций разная базовая частота и разный размах
асимметрии. На этой калибровке стоят три грабли, на каждую я наступил.

**Усиление нельзя калибровать по шуму.** Сначала я ставил его так, чтобы три
сигмы шума давали полный поворот. Вышло 180–200 рад/с, и рулёжка стала
релейной: знак асимметрии прыгал от шума каждый шаг, муха крутилась на месте,
совпадение с градиентом −0,003 в обоих условиях. Теперь усиление берётся так,
чтобы одна сигма **сглаженного** шума давала скромные 0,6 рад/с.

**Сглаживать надо долго.** Перепад концентрации между антеннами в арене около
12 %, а в статическом замере `fly lateral` он 170 %. Сигнал ALPN в арене
оказывается того же порядка, что шум за один шаг управления 20 мс, поэтому
постоянная интегрирования выхода поднята до 0,5 с (`--dn-tau`). Корень из
числа усреднённых шагов даёт выигрыш по шуму примерно в пять раз.

**Коннектом не симметричен.** Слева 341 проекционный нейрон, справа 344, и
проводка у них разная, поэтому у асимметрии есть ненулевое значение покоя. Для
ALPN это **+0,0445 при сигме шума 0,00115** — в 39 раз больше. Умноженный на
усиление, этот перекос один давал постоянный поворот 23 рад/с, то есть
бесконечный круг. Теперь он измеряется в разогреве, когда обе антенны получают
одинаковый вход, и вычитается.

### Где теряется сторона запаха внутри эпизода

```bash
fly arena --t 5 --probe --no-comment
```

Записывает активность нескольких двусторонних популяций и считает корреляцию
между асимметрией входа (запах слева минус справа) и асимметрией популяции.
ORN — это сами стимулируемые нейроны, то есть потолок.

| популяция | r | сигма L−R, Гц | средн., Гц |
|---|---:|---:|---:|
| ORN (вход) | +0,982 | 14,5 | 98,4 |
| ALPN (проекционные) | +0,388 | 1,7 | 99,4 |
| LH (латеральный рог) | +0,279 | 0,9 | 35,2 |
| MBON | +0,067 | 3,9 | 96,9 |
| DN (все 645/646) | +0,019 | 0,7 | 4,1 |
| DNa02 | +0,034 | 41,0 | 30,7 |
| DNa01 | +0,059 | 18,7 | 7,4 |
| DNp09 | −0,137 | 13,1 | 6,6 |

Сторона доживает до антеннальной дольки, наполовину — до латерального рога, а
к нисходящим нейронам исчезает. Усреднение по 645 разнородным нисходящим
нейронам добивает остаток: разброс асимметрии 0,7 Гц при средней частоте
4 Гц — это пуассоновский шум. Отдельные рулевые нейроны не спасают: DNa02 по
одному на полушарие, разброс 41 Гц при средней 31 Гц.

Это разумный результат, а не поломка. Настоящая муха ищет запах во многом
рысканьем головы и временным сравнением, а не мгновенной разницей между
антеннами, и опирается на грудной ганглий, которого в модели нет. Плюс нет
нейромодуляции, которая в живой мухе и открывает путь от обоняния к ногам в
зависимости от голода.

Чтобы контур поехал на запах, пришлось бы либо выбрать узкий выход, который
реально несёт сторону (кандидатов искать через `--probe`), либо добавить
временное сравнение концентрации вместо мгновенного бинокулярного.

### Комментарий по ходу

Локальная модель получает срез состояния раз в 1,5 с — позиция, курс,
скорость, частоты на антеннах, активность нисходящих, самые активные типы
клеток — и пишет одну-две фразы о том, что происходит. Запрос уходит в
рабочий поток, симуляция его не ждёт. В отчёте комментарии стоят на своей
отметке времени, клик перематывает туда.

## Тело: NeuroMechFly v2

```bash
fly body --t 4 --readout ALPN              # эпизод
fly body --t 3 --control                   # контроль: антенны переставлены
fly body --bench 8 --t 3                   # серия с контролем
```

Мозг управляет ногами в MuJoCo. По сравнению с плоской ареной две половины,
которые я раньше придумывал сам, заменены на опубликованные:

* **запах** берётся с антенн мухи в симуляторе (`OdorArena`, четыре датчика:
  две антенны и два щупика), а не считается из гауссова шлейфа;
* **ноги** считает `HybridTurningController` из NeuroMechFly v2 — фазы,
  прилипание, спотыкание и коррекции его.

Придуманными остаются ровно два места, оба отмечены в коде: пересчёт
интенсивности запаха в частоту рецепторов и пересчёт асимметрии нисходящих
в амплитуду шага.

### Какой пакет

Их два, и это важно.

| пакет | импорт | что внутри |
|---|---|---|
| `flygym` 2.1.0 | `flygym` | переписанное ядро: тело, мир, физика, зрение, рендер. **Контроллера походки нет** |
| `flygym-gymnasium` 1.3.2 | `flygym_gymnasium` | NeuroMechFly v2 из статьи: тело **плюс** контроллер ходьбы с нисходящим управлением |

Нужен 1.x. В марте 2026 FlyGym переписали, ядро стало быстрее, но контроллер
походки в 2.x не перенесли, а в комплекте нет ни CPG, ни записанных шагов —
только модель. Писать походку самому означало бы снова выдумывать то, чего
коннектом не даёт.

Имена импорта разные, так что оба пакета спокойно стоят рядом.

### Что это стоило окружению

`flygym-gymnasium` тянет `numba==0.60.0`, который требует **numpy < 2.1**, так
что numpy понижен с 2.5.4 до 2.0.2. На мозг это не повлияло: `fly verify`
после понижения даёт те же 403 активных нейрона и 17 393 спайка, что и до,
корреляция с апстримом 0.9941.

Если ставите заново — закройте пульт перед установкой: Windows не даёт
перезаписать файлы numpy, пока их держит работающий процесс.

### Интерфейс и знаки

```python
from flygym_gymnasium.examples.locomotion import HybridTurningController
sim.step(action)   # action: np.ndarray формы (2,) — нисходящий сигнал поворота
```

Из кода контроллера: `action[0]` задаёт амплитуду шага **левых** трёх ног,
`action[1]` — правых, знак задаёт направление, диапазон (−0,5; 1,5).

Два знака пришлось установить замером, а не угадывать.

**Какой датчик левый.** Поставил источник запаха в +y и в −y и сравнил
показания: при источнике слева больше первый датчик, при источнике справа —
второй. Значит, порядок `[левая антенна, правая антенна, левый щупик,
правый щупик]`.

**Куда поворачивает муха.** Команда `[1, 0.2]` (левые ноги сильнее) даёт
смещение +2,53 и −1,77 мм, то есть вправо. Поэтому связь мозга с ногами
**перекрёстная**: левое полушарие управляет правыми ногами, иначе муха
уходила бы от запаха. Переключается флагом `--no-cross`.

### Замер на этой машине

`lab/bench_body.py`, ходьба по ровному полу, без рендера:

| шаг физики | шагов/с | от реального времени | скорость ходьбы |
|---|---:|---:|---|
| 0,1 мс | 461 | 0,047× | 12,7 мм/с |
| 0,2 мс | 407 | 0,081× | 13,6 мм/с |

Команда `[1, 1]` даёт ход прямо, `[1, 0.2]` — поворот направо (смещение
+2,53 и −1,77 мм). Скорость правдоподобная: настоящая муха ходит 10–20 мм/с.

Шагов в секунду при удвоении шага физики не выросло (461 → 407), то есть
время уходит не в интегрирование MuJoCo, а в питоновский контроллер, который
крутится на частоте физики. Поэтому удвоение шага почти удваивает скорость
и ничего не ломает в походке.

**Эти две строки — прежние, до ускорения.** Нынешние числа сняты
перемежающимися парами на полном контуре и разобраны в
`lab/flybrain/PERFORMANCE_V2.md`:

| составляющая | было | стало |
|---|---:|---:|
| шаг управления (20 мс модельных) | 337,41 мс | **179,28 мс** |
| мозг (LIF, синхронизация, учёт) | 73,93 | **37,41** |
| физика MuJoCo (100 шагов) | 262,81 | **141,34** |
| доля реального времени | 0,0593× | **0,1004…0,1116×** |

Секунда жизни мухи обходится теперь примерно в девять секунд
счёта вместо двадцати, а серия из двадцати эпизодов по 5 с — около
пятнадцати минут вместо получаса.

**Узкое место по-прежнему тело, и теперь сильнее:** физика занимает
78,8 % шага, мозг 20,9 %. Притом внутри самой «физики» далеко не всё
— MuJoCo: две трети там сам решатель, а остальное — сборка
наблюдения и контроллер походки на Python.

## Сверка с апстримом

```bash
fly verify --t 1.0
```

Гоняет тот же эксперимент здесь и апстримным бэкендом PyTorch и сравнивает
активные множества (Jaccard) и корреляцию частот. Уравнения, параметры, порядок
обновления состояния и матрица весов общие; различается только генератор
случайных чисел для пуассоновского входа.

Результат на эксперименте `sugar`, 1 с, 1 прогон:

```
активных: мой 403, апстрим 412
Jaccard по активным нейронам: 0.922
корреляция частот: 0.9904
суммарные спайки: мой 17393, апстрим 17371
```

Расхождение в 0,1 % по спайкам — это разные случайные последовательности

## Если что-то не запускается

**`uv trampoline failed to spawn Python child process`.**

```bash
D:\fly-brain\fix-venv.cmd
```

uv хранит путь к базовому интерпретатору **внутри** трамплина
`.venv\Scripts\python.exe`, и путь этот ведёт в папку без номера патча —
`...\uv\python\cpython-3.12-windows-x86_64-none`, которая на самом деле
junction на настоящую `cpython-3.12.13-...`. Когда uv чистит кэш, junction
пропадает, и падает всё подряд. Править `pyvenv.cfg` бесполезно: трамплин его
не читает. `fix-venv.cmd` вычисляет нужное имя из `pyvenv.cfg` и создаёт
junction заново. Если и сам интерпретатор исчез — он скажет пересобрать
окружение.

**Кракозябры или странные ошибки вида `'Починить:' is not recognized`.**
Так было, пока батники звали `chcp 65001`. cmd.exe считает позицию в файле
байтами, и смена кодовой страницы посреди чтения разрезает оставшиеся строки
не там, где надо, — куски уходят на исполнение как команды. Поэтому все `.cmd`
здесь строго ASCII и кодовую страницу не трогают, а русский вывод печатает
Python в родной кодировке консоли. Если будете дописывать свои батники —
не ставьте в них `chcp`.

**Комментария локальной модели нет.** Проверьте, что Ollama отвечает:
`curl http://127.0.0.1:11434/api/tags`. Симуляция в этом случае всё равно
отрабатывает, в отчёте просто нет блока с комментарием.
